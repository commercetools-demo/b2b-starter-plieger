# B2B Starter — commercetools + Claude Code

A fully functional B2B ecommerce storefront built with **Next.js 15**, **React 19**, **TypeScript**, **Tailwind CSS v4**, and **commercetools**. Every line of code — the storefront, admin tools, and seed scripts — was generated by [Claude Code](https://docs.anthropic.com/en/docs/claude-code) from plain-English instructions.

Fork it, connect your own commercetools project, and use Claude Code to customize it into your own demo.

---

## What You Get

- **Product catalog** with category browsing, full-text search, and store-specific pricing
- **Product detail pages** with variant support, image gallery, and inventory availability
- **Business units** — companies and divisions with hierarchical structure, multi-store support
- **Associate roles** — admin, buyer, and approver roles with 30+ granular permissions
- **Shopping cart** — store-scoped carts with discount codes
- **Checkout** with shipping/billing addresses and purchase order numbers
- **Quotes** — request quotes, negotiate pricing, accept or decline
- **Approval workflows** — multi-tier approval rules with predicate-based conditions
- **Purchase lists** — shared shopping lists within a business unit
- **Dashboard** with order history, pending quotes, pending approvals, and company management
- **Admin tools** (`tools/`) for seeding demo data, setting up roles, and business units

See **[FEATURES.md](FEATURES.md)** for the complete feature inventory with implementation details.

## Quick Start

### 1. Fork This Repo

1. Click the **Fork** button at the top-right of this page
2. Set the **Owner** to the `commercetools-demo` org
3. Give it a name that fits your demo (e.g., `acme-b2b-storefront`)
4. Click **Create fork**

Then clone your fork:

```bash
git clone https://github.com/commercetools-demo/YOUR-REPO-NAME.git
cd YOUR-REPO-NAME
```

### 2. Activate the Product Search API

The storefront uses the commercetools Product Search API, which must be activated before use:

- **Merchant Center** → Project Settings → activate Product Search
- Or activate via the API

If not activated, product listing and detail pages will fail with a 404/ObjectNotFound error.

### 3. Set Up commercetools Credentials

You need two API clients in your CT Merchant Center (**Settings > Developer > API Clients**):

**Storefront client** (`site/.env`):
- Use the **Frontend B2C** template as a base
- Add scopes: `manage_business_units`, `manage_quote_requests`, `manage_quotes`, `manage_approval_flows`, `manage_approval_rules`, `manage_shopping_lists`, `manage_orders`
- Copy `site/.env.example` to `site/.env` and fill in credentials

**Admin client** (`tools/.env`) — for seeding demo data:
- Use the **Admin client** template
- Copy `tools/.env.example` to `tools/.env` and fill in credentials

> **Warning:** `.env` files contain secrets and are gitignored. **Never commit them.** If you accidentally commit a `.env` file, rotate your API client credentials immediately in Merchant Center.

### 4. Install and Seed Data

```bash
# Install dependencies
cd site && npm install
cd ../tools && npm install

# Seed demo data (one-time — only if project has no data)
cd tools && node seed-sample-data.mjs
```

### 5. Run the Storefront

```bash
cd site
npm run dev
```

Open http://localhost:8888

## Deploy to Netlify

`netlify.toml` is pre-configured. To deploy:

1. Push your fork to GitHub
2. In [Netlify](https://app.netlify.com), click **Add new site > Import an existing project**
3. Connect your GitHub repo — build settings are auto-detected from `netlify.toml`
4. Set **Base directory** to `site`
5. Add your `site/.env` variables in **Site configuration > Environment variables**
6. Deploy

Every push to **main** triggers an automatic redeploy.

### Required Environment Variables

| Variable | Description |
|---|---|
| `CTP_PROJECT_KEY` | commercetools project key |
| `CTP_CLIENT_ID` | Storefront API client ID |
| `CTP_CLIENT_SECRET` | Storefront API client secret |
| `CTP_AUTH_URL` | CT auth URL |
| `CTP_API_URL` | CT API URL |
| `CTP_SCOPES` | API client scopes |

## Using Claude Code

This project includes a `CLAUDE.md` file that gives Claude Code full context about the architecture, patterns, and conventions. Open the repo in Claude Code and start asking for changes:

- *"Add a reorder button to past orders"*
- *"Change the branding to match our company"*
- *"Add a product comparison feature"*
- *"Create an approval rule that requires manager sign-off for orders over $10,000"*
- *"Write a tool that lists all business units and their associates"*

Claude Code will explore the codebase, understand the patterns, make changes, and verify them.

### The `tools/` Directory

Instead of wiring up MCP servers or writing API calls by hand, just ask Claude Code:

> *"Write a tool that lists all products without images and put it in tools/"*

It follows the existing pattern — imports from `ct-admin.mjs`, uses the admin `.env`, and produces a standalone script you can run anytime.

### Adding Features Without Breaking Things

Two files work together as guardrails:

| File | Purpose |
|---|---|
| `CLAUDE.md` | Tells Claude Code the architecture rules and conventions |
| `FEATURES.md` | Complete inventory of what's implemented — Claude Code reads this before making changes |

**Recommended workflow:**

1. Tell Claude Code what you want — *"Add a budget management feature for business units"*
2. Claude Code reads `CLAUDE.md` and `FEATURES.md` automatically, so it knows the architecture and what exists
3. Claude Code implements the feature
4. Claude Code updates `FEATURES.md`

## Key B2B Concepts

### Business Units & Stores
Users are **associates** of business units. Each business unit has assigned **stores**, and carts/orders are scoped to a specific store. Different stores see different products and different prices — this is a core B2B demo feature.

### Associate Roles & Permissions
Associates have roles (admin, buyer, approver) with **30+ granular permissions** covering carts, orders, quotes, approvals, shopping lists, and business unit management. The storefront enforces permissions at both the UI and API level.

### Quotes (Price Negotiation)
Buyers can request a quote from their cart. Sellers respond with adjusted pricing. Buyers can accept, decline, or renegotiate. The full lifecycle is tracked in the dashboard.

### Approval Workflows
Admins define **approval rules** with conditions (e.g., "orders over $5,000 require approval"). When an order matches a rule, it enters an **approval flow** with multi-tier approver chains. Designated approvers can approve or reject with reasons.

### Purchase Lists
Shared shopping lists within a business unit. Associates can create lists, add products, and share them with team members based on permissions.
